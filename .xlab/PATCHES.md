| Plugin event and SDK read for execution-policy stage decisions, with reviewed SHA (`issue.execution_decision.recorded`, `ctx.issues.listExecutionDecisions`) | `feat/APP-43-execution-decision-event` | Review and approval stage decisions were visible to plugins only through a generic `issue.updated`, and nothing recorded which commit was reviewed, so a plugin (the GitHub approval gate) could not act on a Code Reviewer's approval of an exact commit. | Sandbox `/tmp` 8Gi; exec failures without an exit code keep the Kubernetes status | `APP-128-incident-sandboxed-agent-runs-fail-in-the-post-run-git-export-step-git-delta-bundle-exit-1-so-their-work-is-lost` | A run puts HOME, XDG dirs and provider homes under `/tmp`, so package stores and build caches filled the 2Gi emptyDir and the kubelet evicted the pod mid-run; the post-run git export then failed with a bare "exit code 1" because `execInPod` dropped the status message of an exec that had no `ExitCode` cause. `/tmp` is now 8Gi (same as `/workspace`), and that status goes into stderr | Not yet offered |
| Kubernetes exec transfers with flow control | `fix/k8s-exec-stream-backpressure` | `@kubernetes/client-node` 1.4.0 sends exec stdin the moment it is read and writes stdout frames without checking `write()`, so a native `syncIn` queued the whole workspace tarball in the WebSocket send buffer and a restore whose disk was slower than the network held the archive in the stdout stream. The plugin worker's memory grew with every transfer and did not come back (server pod OOM-killed at 3Gi with 10-16 sandboxes, 2026-11-23). `execInPodStreaming` now sends stdin itself with a 1 MiB window and pauses the WebSocket while the stdout sink is full | Not yet offered; generic, upstream candidate |
| Typecheck in agent sandboxes: one tsc thread under a small cgroup limit, `AGENTS.md` rules | `APP-223-agent-sandboxes-oom-at-4gi-on-a-paperclip-server-typecheck-measure-and-set-the-limit` | Agents ran `tsc` on the whole server program (more than 8 GiB) or the layered server typecheck at the default checkers (3.4 GiB in its first layer) in 4 GiB sandboxes. The sandbox cgroup kills as a group, so each OOM took the agent with it and Paperclip retried into the same kill: 18 runs lost on 22-24 Nov 2026 (APP-223). `scripts/run-tsc.mjs` now uses `--singleThreaded` when the cgroup memory limit is below 8 GiB, and `AGENTS.md` says which typecheck to run in a sandbox | Not yet offered |
| A killed run never revokes a shared AI subscription | `APP-199-one-agent-run-that-was-oom-killed-revoked-the-company-s-shared-claude-subscription-false-claude_auth_required` | An agent run OOM-killed during a typecheck was classified `claude_auth_required` because the login-prompt match scanned the agent's own stream-json tool output, and that one run revoked the company's shared Claude grant (twice on 2026-11-24). The claude_local adapter now matches login prompts only on plain-text CLI lines, never classifies a signal or exit 137/143 as a login failure, and the server probes a shared grant before revoking it, revoking only on a 401 | Not yet offered; generic, upstream candidate |
| Plugin workers sandboxed with the Node permission model (`PAPERCLIP_PLUGIN_WORKER_SANDBOX`) | `APP-37-build-sandbox-plugin-workers-so-they-cannot-read-host-secret-files` ([#78](https://github.com/applyinnovations/paperclip/pull/78)) | Security fix. Workers were `fork()`ed with the server's full filesystem access, so any plugin could read the approvals App key and the per-company App keys. Workers now run under `--permission` with reads limited to their package, resolution paths and configured local folders, and writes to their data/tmp dirs; a worker whose allowlist would cover a GitHub App key or apps file is refused. Image-bundled plugins that need child processes (sandbox providers, workspace readers) run unsandboxed as trusted exceptions. Every worker and the server run with `--disable-sigusr1`, and the image sets `NODE_OPTIONS=--disable-sigusr1` for every other Node process (no inspector via signal), sandboxed workers get `--no-experimental-sqlite`, and local-folder roots over secret files, secret mounts, `/proc`, `/etc` or host code (install root, plugin catalog, plugin and adapter install dirs) are refused. `off` disables the sandbox for local development | Not yet offered |
